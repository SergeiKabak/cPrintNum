# PrintNum — статус проекта и план работ

Документ отвечает на три вопроса: **что уже работает**, **что делаем дальше**,
**что лежит в бэклоге и почему пока не сделано**.

- Текущая версия: **v2.1.0** (тег `v2.1.0`, релиз опубликован)
- Репозиторий и CI/CD: <https://github.com/SergeiKabak/cPrintNum>
- Страницы для операторов: <https://sergeikabak.github.io/cPrintNum/>
- Техническая база знаний: [`README.md`](../README.md) (единый KB, ~1500 строк)

## 1. Что сделано

### 1.1. Печать и сервер (C, Windows 7 x64)

| Готово | Детали |
|---|---|
| ✅ Служба без CRT | `-nostdlib`, только системные DLL Win7; CI проверяет отсутствие `api-ms-win-crt` |
| ✅ HTTP API на 5000 | `GET /`, `/config`, `/papers`, `/listPrinters`, `/status-printer`, `/service`; `POST /config`, `/print-number`, `/print-barcode`, `/service/install|uninstall` |
| ✅ Два режима печати | GDI (через драйвер) и RAW ESC/POS (`ESC @`, `GS v 0`, `ESC J`) |
| ✅ Этикетка ячейки | номер 1–4 цифры (`163-1`, `12`, `5-3`), контрольная клетка с контуром, полка `-88` |
| ✅ QR на этикетке | порт ricmoo/QRCode, авто-выбор версии и максимального модуля |
| ✅ «Номер + QR товара» | режим `qrWithNumber`, QR справа от номера |
| ✅ Предпросмотр вместо печати | `previewDir` → BMP-файлы, принтер не нужен |
| ✅ Производительность | общие scratch-буферы, bbox, единый `LabelSurface`, печать одним `BitBlt`, LRU-кэш QR (8 слотов), таймаут `recv` 5 с |
| ✅ Диагностика | `--demo-cell-qr`, `--raw-dump`, лог службы `%APPDATA%\PrintNum\log.txt` |

### 1.2. Расширение (WXT + Preact + TS)

| Готово | Детали |
|---|---|
| ✅ Печать ячейки в один клик | popup → `/print-number`, валидация на клиенте и сервере |

| ✅ Popup-настройки | принтер, бумага, гап, контрольная клетка, контур, QR рядом с номером, режим предпросмотра |

| ✅ Эмулятор сканера | `PrintNumScan.pick()` в консоли страницы для тестов без железа |

### 1.3. Должники (неоплаченные заказы)

| Готово | Детали |
|---|---|
| ✅ Локальная база | popup → «Должники»: `clientId` + имя + заметка, CRUD, импорт/экспорт JSON |

## 2. Следующее: версия 2.2.0

Состав релиза — две темы: **блокировка выдачи должнику** и выпуск обновления.

### 2.1. `giveoutGuard` — не дать выдать заказ должнику

Сейчас фича только предупреждает плашкой; кнопку «Выдать» оператор всё равно
может нажать. Модуль `extension/src/utils/giveoutGuard.ts` **уже написан**
(ищет кнопки по тексту, ставит `disabled`/`pointer-events`, гасит клик в
capture-фазе, держит баннер, перепроверяет DOM на мутациях и раз в 700 мс),
но **не подключён к потоку данных**. Осталось:

- [x] `pageHook`: сообщение `GIVEOUT { sessionId, clientId, clientName, codes }`
      из `Postings`/`Sessions` **и** из `order-condition/Session/search-v2`
      (`clientInfo.id` + `shortName`, `giveoutInfo.sessionId`);
- [x] `debtorWatch`: `evaluateGiveout()` → должник по `clientId` →
      `applyGiveoutGuard({ clientId, name })`; не должник — снятие блокировки;
- [x] третий триггер: код выдачи `<clientId>*<NNNN>` в поле сканера —
      блокировка сразу при вводе, до ответа API;
- [x] настройка `debtorBlockGiveout` (по умолчанию `true`) + чекбокс
      «Блокировать кнопку «Выдать» у должника» в панели «Должники»;
- [x] плашка и баннер показывают `shortName` из ответа Ozon;
- [x] проверено на живом Ozon (Chrome 158, вкладка ПВЗ): ввод `89367626*0328`
      → баннер «Выдача заблокирована: Сергей К. (должник)», кнопка «Выдать»
      `disabled` + `pointer-events: none`, в т.ч. после SPA-перехода
      «К выдаче»; код не-должника блокировку снимает;
- [ ] README §4.19 — как устроена блокировка и её ограничения
      (кнопка ищется по тексту: «выдать», «завершить», «подтвердить»);
- [ ] честно оценить риск ложных срабатываний: если Ozon нарисует кнопку
      без текста (иконка) — блокировка не сработает, нужен лог-предупреждение.

**Ограничение, о котором надо помнить:** блокировка на уровне DOM не
защищает от выдачи, начатой другим путём (другая вкладка, мобильное
приложение, прямой вызов API). Это защита от случайного клика оператора,
а не контроль доступа.

### 2.2. Выпуск 2.2.0

- [ ] поднять версию в `extension/package.json` и `wxt.config.ts`
      (`2.1.0` → `2.2.0`), синхронно;
- [ ] обновить этот документ и `README` (раздел про должников);
- [ ] прогнать локально: `./build.sh`, `./wine-ctl.sh restart && ./wine-ctl.sh test`
      (27/27), `cd extension && npm run compile && npm run build`;
- [ ] push → зелёный CI (три job'а);
- [ ] `git tag v2.2.0 && git push origin v2.2.0` → CI соберёт релиз;
- [ ] в релиз-ноутах по-человечески: «блокировка выдачи должнику»,
      «имя клиента в предупреждении», «связка отправление ↔ клиент».

## 5. Шпаргалка по выпуску версии

```bash
# 1. версия
$EDITOR extension/wxt.config.ts extension/package.json      # 2.2.0

# 2. проверки
./build.sh
./wine-ctl.sh restart && ./wine-ctl.sh test                 # 27/27
cd extension && npm run compile && npm run build && cd ..

# 3. релиз
git add -A && git commit -m "Release 2.2.0: …"
git push origin main
git tag v2.2.0 && git push origin v2.2.0                    # CI соберёт и опубликует

# 4. после релиза
gh release view v2.2.0 -R SergeiKabak/cPrintNum
curl -sI https://github.com/SergeiKabak/cPrintNum/releases/latest/download/install.ps1
```

Обновление у оператора: распаковать новый архив поверх папки (сохранив
`config.json`) → в `chrome://extensions` нажать «Обновить» → **F5 на вкладке
Ozon** (иначе работает старый `pageHook`).
