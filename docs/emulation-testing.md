# PrintNum — эмуляция для тестирования

Как проверить работу приложения **без реального принтера и без сканера ШК**.

В проекте есть два независимых эмулятора:

- **Эмуляция печати (dry-run)** — в самом приложении PrintNum: вместо отправки на
  принтер этикетка рендерится и сохраняется как изображение + отчёт.
- **Эмуляция сканирования ШК** — в браузерном расширении: программно генерируются
  те же события клавиатуры, что и от физического сканера.

## 1. Эмулятор печати (dry-run)

Самый быстрый способ увидеть, что будет напечатано, — без расширения и браузера.

### Запуск (Windows)

```bat
cd src-printnum
cargo run --release -- --dry-run
```

Или с готовым бинарником:

```bat
printnum.exe --dry-run
```

Через переменную окружения:

```bat
set PRINTNUM_DRY_RUN=1
printnum.exe
```

### Запуск (macOS / Linux — только для разработки)

```bash
cd src-printnum
cargo run -- --dry-run
```

> На macOS/Linux изображение не рендерится (нет GDI), но режим работает и
> логируется. BMP-превью создаётся только на Windows.

### Как понять, что режим включён

Откроется окно приложения. Внизу справа должен быть индикатор **«РЕЖИМ ЭМУЛЯЦИИ»**.
В консоли при старте выводится:

```
*** РЕЖИМ ЭМУЛЯЦИИ ПЕЧАТИ (dry-run) ***
Печать на принтер выполняться НЕ будет.
Превью сохраняются в: <каталог данных>\PrintNum\previews   (Windows)
Превью сохраняются в: /Users/<Имя>/Library/Application Support/PrintNum/previews   (macOS)
```

Точный каталог см. в таблице путей ниже; программа выводит его при старте.

### Отправка номеров

В **другом** терминале (приложение должно быть уже запущено):

```bash
curl -X POST http://127.0.0.1:5000/print-number \
  -H "Content-Type: application/json" -d "{\"text\":\"500-47\"}"
```

Разные сценарии логики:

```bash
curl -X POST http://127.0.0.1:5000/print-number -H "Content-Type: application/json" -d "{\"text\":\"123-47\"}"
curl -X POST http://127.0.0.1:5000/print-number -H "Content-Type: application/json" -d "{\"text\":\"500-47\"}"
curl -X POST http://127.0.0.1:5000/print-number -H "Content-Type: application/json" -d "{\"text\":\"КГТ-1\"}"
```

### Где смотреть результат

Каталог данных зависит от платформы:

| Платформа | Каталог превью |
| --------- | -------------- |
| **Windows** | `%APPDATA%\PrintNum\previews\` |
| **macOS** (только разработка) | `~/Library/Application Support/PrintNum/previews/` |
| **Linux** (только разработка) | `~/.config/PrintNum/previews/` (или `$XDG_CONFIG_HOME/PrintNum/previews/`) |

Для справки на Windows `%APPDATA%` — это
`C:\Users\<Имя>\AppData\Roaming`.

Для каждого вызова создаются два файла:

- `label_<текст>_<время>.bmp` — **изображение этикетки** (открывается любым просмотрщиком);
- `label_<текст>_<время>.json` — **отчёт** с вычисленными параметрами.

Пример отчёта:

```json
{
  "text": "500-47",
  "main_text": "47.",
  "header_text": "500-",
  "is_bold": true,
  "is_underlined": false,
  "paper": "30*20",
  "label_px": { "width": 239, "height": 159 },
  "margin_px": { "x": 11, "y": 7 },
  "main_font_height_px": 71,
  "main_rect": { "x": 85, "y": 55, "w": 68, "h": 62 }
}
```

В консоли приложения при этом выводится:

```
[dry-run] Этикетка отрендерена (печать не выполнялась).
[dry-run] Разбор номера:
  Вход:        "500-47"
  Основной:    "47."
  Колонтитул:  "500-"
  Жирный:      да
  Рокировка:   да
  Подчёркивание: нет
  Этикетка:    30*20 мм
  Параметры:   hybrid=true, idNum=true, endLine=false, expand=500
[dry-run] Шрифт: 71px, жирный: true
[dry-run] Отчёт: ...\previews\label_500-47_....json
[dry-run] Превью: ...\previews\label_500-47_....bmp
```

### На macOS/Linux (без GDI)

Картинка не рендерится, но **разбор номера всё равно выводится** — этого
достаточно, чтобы проверить логику (swap, жирность, КГТ) без Windows:

```
[dry-run] Рендер этикетки недоступен вне Windows (нет GDI).
[dry-run] Разбор номера:
  Вход:        "КГТ-1"
  Основной:    "1."
  Колонтитул:  "КГТ-"
  Жирный:      да
  Рокировка:   да
  Подчёркивание: нет
  Этикетка:    30*20 мм
  Параметры:   hybrid=false, idNum=false, endLine=false, expand=500
```

### Примеры разбора разных номеров

При `hybrid=true`, `idNum=true`, `expand=500`:

| Вход | Основной | Колонтитул | Жирный | Рокировка |
| ---- | -------- | ---------- | ------ | --------- |
| `123-47` | `123.` | `-47` | нет | нет |
| `499-47` | `499.` | `-47` | нет | нет |
| `500-47` | `47.` | `500-` | да | да |
| `501-47` | `47.` | `501-` | да | да |
| `КГТ-2` | `2.` | `КГТ-` | да | да |

> Обратите внимание: `КГТ-*` становится жирным и меняет порядок **даже при
> `hybrid=false`** — так задумано.

## 2. Эмулятор сканирования ШК

Проверяет цепочку `listener.ts → content script → отправка номера` без физического
сканера. Доступен **только в dev-режиме** расширения.

### Шаг 1. Запустите PrintNum в режиме эмуляции печати

```bat
cd src-printnum
cargo run --release -- --dry-run
```

Пусть окно приложения работает — оно слушает `127.0.0.1:5000`.

### Шаг 2. Запустите расширение в dev-режиме

```bat
cd extension
npm install          :: только в первый раз
npm run dev
```

WXT соберёт расширение в `extension\output\chrome-mv3`.

### Шаг 3. Загрузите расширение в браузер

1. Откройте `chrome://extensions`
2. Включите **Режим разработчика**
3. **Загрузить распакованное** → выберите папку `extension\output\chrome-mv3`

### Шаг 4. Откройте Ozon и консоль

1. Перейдите на `https://turbo-pvz.ozon.ru/...`
2. Нажмите **F12** → вкладка **Console**

### Шаг 5. Симулируйте сканирование

В консоли браузера:

```js
// одиночное сканирование
PrintNumScanner.simulate("123-47");

// серия сканирований с паузами между ними
PrintNumScanner.simulateSequence(["123-47", "500-47", "КГТ-1"], 1500);
```

> ⚠️ **Контекст DevTools.** Модули content script живут в **изолированном мире**
> расширения, а не в мире страницы. Если в консоли выбрать контекст **top/page**,
> переменная `PrintNumScanner` будет не определена и вы увидите:
> `Uncaught ReferenceError: PrintNumScanner is not defined`.
>
> В панели **Console** переключите выпадающий список контекста (рядом с `top`)
> на **PrintNum** — тогда `PrintNumScanner` станет доступен.
>
> Альтернатива: `wxt dev` открывает Chrome с уже загруженным расширением —
> используйте именно его.

### Где смотреть логи

Логи разделены по двум разным местам — не путайте их:

| Источник | Где видно | Пример строки |
| -------- | --------- | ------------- |
| **Расширение** (content script) | Консоль браузера (DevTools) | `[PrintNum:scanner] отсканировано: "123-47"` |
| **Приложение** (HTTP-сервер, печать) | Терминал, где запущен `printnum` / `cargo run` | `[dry-run] Разбор номера: ...` |

Ожидаемая последовательность при успешной симуляции (в консоли браузера):

```
[PrintNum:scanner] отсканировано: "123-47"
[PrintNum:scanner] обработка номера: "123-47"
[PrintNum:scanner] номер "123-47" отправлен в PrintNum
```

Если последней строки нет — номер не дошёл до приложения. Проверьте, что
`printnum` запущен и слушает тот же порт.

### API эмулятора

| Функция                                                     | Описание                                            |
| ----------------------------------------------------------- | --------------------------------------------------- |
| `simulate(value, charDelay = 15)`                           | Симулирует сканирование одного ШК                   |
| `simulateSequence(values, delayMs = 1500, charDelay = 15)`  | Серия сканирований с паузой между ними              |
| `onSimulatedScan(callback)`                                 | Подписка на результат симулированного сканирования  |

Эмулятор генерирует **реальные события `keydown`** на `window` — точно так же,
как это делает сканер. Поэтому проверяется боевой код `utils/listener.ts`, а не
его копия.

### Где смотреть результат

- **консоль браузера** (расширение): `[PrintNum:scanner] номер "123-47" отправлен в PrintNum`
- **терминал приложения**: строка о печати/эмуляции (например, `[dry-run] ...`)
- **каталог `previews`** (см. таблицу путей в разделе 1): новый `.bmp` + `.json`
  для каждого номера (только на Windows)

> В production-сборке (`npm run build`) эмулятор сканера **вырезается** из бандла —
> он доступен только при `npm run dev`.

## 3. Полный сквозной тест

Проверяет всю цепочку «сканирование → печать» без реального оборудования.

**Терминал 1** — приложение в режиме эмуляции печати:

```bat
cd src-printnum
cargo run --release -- --dry-run
```

**Терминал 2** — расширение в dev-режиме:

```bat
cd extension
npm run dev
```

**Браузер** — загрузить расширение из `output\chrome-mv3`, открыть Ozon, F12,
в консоли:

```js
PrintNumScanner.simulateSequence(["123-47", "500-47", "КГТ-1"], 1500);
```

**Результат** — в каталоге `previews` (см. таблицу путей) появятся три пары файлов
(`.bmp` + `.json`) — по одному на каждый «отсканированный» номер, без единой
реальной печати и без сканера.

## 6. Важные замечания

1. **`--dry-run` обязателен.** Без него приложение попытается печатать на реальный
   принтер. В режиме dry-run принтер **не нужен** — номер доходит до логики печати
   и логируется; в боевом режиме без выбранного/доступного принтера будет строка
   `[print] пропуск: принтер не выбран`.
2. **Порт 5000** должен быть свободен. Приложение должно быть запущено **до**
   `curl` и до отправки из расширения. Если порт занят — см. раздел 7.
3. **BMP-превью создаётся только на Windows** (нужен GDI). На macOS/Linux режим
   работает и логирует разбор номера (см. раздел 1), но изображение не рендерится.
4. Для симуляции сканера нужен именно **`npm run dev`** (не `npm run build`) —
   иначе `PrintNumScanner` в консоли будет `undefined`.
5. Настройки эмуляции берутся из того же `config.json` (рядом с каталогом `previews`),
   что и при обычной работе. Допустимый бумажный размер и порог `expand` можно менять
   в настройках приложения.

## 7. Смена порта

Порт по умолчанию — `5000`. На macOS его часто занимает системный AirPlay Receiver,
поэтому для тестов порт стоит сменить.

### В приложении

Создайте файл `.env` рядом с `printnum.exe` (при `cargo run` — в папке
`src-printnum/`) либо задайте переменную окружения:

```env
PRINTNUM_PORT=6000
```

Приоритет: переменная окружения → `.env` → `5000`.

Проверить выбранный порт можно по строке в консоли при старте:

```
HTTP сервер запущен на http://127.0.0.1:6000
```

### В расширении

Укажите **тот же** порт в `extension/.env` и пересоберите расширение:

```env
VITE_PRINTNUM_PORT=6000
```

```bash
cd extension
npm run dev      # или npm run build
```

> Порт подставляется в расширение **на этапе сборки**, а не во время работы.
> Без пересборки расширение продолжит стучаться на старый порт.
>
> Также для симуляции сканера в консоли создайте `.env` **до** `npm run dev`,
> иначе подставится порт по умолчанию `5000`.

### curl с другим портом

После смены порта используйте его во всех запросах:

```bash
curl -X POST http://127.0.0.1:6000/print-number \
  -H "Content-Type: application/json" -d "{\"text\":\"500-47\"}"
```
