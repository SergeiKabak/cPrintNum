# Сравнение: Preact vs Vanilla TS для popup расширения

Документ с замерами, чтобы решить, чем заменить React в popup расширения
(чтение DOM Ozon и печать от React **не зависят** — см. ниже).

## Контекст

React в расширении используется **только в popup** (окно настроек).
Все 13 content scripts, включая чтение DOM Ozon (`querySelectorAll`,
`MutationObserver`) и авто-печать, — **чистый TypeScript без React**.

| Часть расширения | React | Размер |
| ---------------- | ----- | ------ |
| 13 content scripts (чтение DOM, печать) | ❌ | ~15 КБ каждый |
| popup (настройки, QR, справка) | ✅ React + Radix | **200 КБ** (61.5 КБ gzip) |

То есть замена React касается только popup.

## Размер бандла

Замер на одинаковом UI (список раскрывающихся секций + кнопки, как в popup),
сборка `esbuild --bundle --minify`.

### Без внешних UI-библиотек

| Вариант | Размер | gzip | Отношение к React |
| ------- | ------ | ---- | ----------------- |
| **React + Radix** (текущий) | 199 792 Б | **61.5 КБ** | — |
| **Preact** | 14 206 Б | **5.7 КБ** | — 91 % |
| **Vanilla TS** | 1 418 Б | **0.6 КБ** | — 99 % |

> React тянет `react-dom` + `scheduler` + 10 пакетов Radix UI.
> Preact — только ядро (3 КБ) + hooks.
> Vanilla — ничего, кроме вашего кода.

### ⚠️ Важно: с Radix UI выигрыша НЕТ

Проверено на реальном коде popup (тот же `@radix-ui/react-accordion`):

| Сборка | gzip |
| ------ | ---- |
| React + Radix | **12.9 КБ** |
| Preact (`preact/compat`) + Radix | **17.5 КБ** |

**С `preact/compat` бандл получился БОЛЬШЕ, чем с React.** Причины:

- `preact/compat` тянет дополнительный слой совместимости;
- Radix UI написан под React и использует его внутренности;
- большая часть веса — это **Radix**, а не сам React.

**Вывод:** чтобы получить выигрыш Preact, нужно убрать **и Radix UI**, заменив
компоненты на простые собственные (аккордеон/диалог/переключатель на Preact).
Только тогда работает соотношение 61.5 → 5.7 КБ.

> В реальном popup используются только `accordion` и `button` из UI-компонентов —
> их легко переписать вручную на Preact без Radix.

**Экономия (при отказе от Radix):** Preact экономит ~56 КБ gzip, Vanilla — ~61 КБ gzip.

> Для расширения это не критично: popup загружается локально, не по сети.
> Но меньше кода — меньше поверхность уязвимостей (`npm audit`) и быстрее `npm install`.

## Скорость работы

Замер в headless Chrome, одинаковый объём работы. Один «тик» = полное обновление
списка `n` элементов (пересоздание для vanilla, diff для Preact).

### Реалистичный размер popup — 50 элементов

| Тест | Preact | Vanilla TS |
| ---- | ------ | ---------- |
| Латентность одного обновления (со синхронизацией кадра) | ~33 мс | ~33 мс |
| 500 последовательных обновлений | **203 мс** | **815 мс** |

На одиночном обновлении разницы нет (упираемся в кадр рисования).
На множественных обновлениях **Preact в ~4 раза быстрее** — за счёт батчинга
и обновления только изменившихся узлов.

### Стресс — 2000 элементов

| Тест | Preact | Vanilla TS |
| ---- | ------ | ---------- |
| Полный цикл обновления | **33 мс** | **67 мс** |

Preact меняет только изменившийся текст, vanilla пересоздаёт весь список.

### Вывод по скорости

- **Popup с редкими обновлениями** (настройки, переключатели): разницы нет.
- **Частые обновления** (живой список, динамика): Preact заметно быстрее.
- Vanilla требует **ручного** управления DOM: чтобы не тормозить, придётся
  самому писать точечное обновление узлов (то, что Preact делает автоматически).

## Удобство разработки

| Критерий | Preact | Vanilla TS |
| -------- | ------ | ---------- |
| Синтаксис | JSX, компоненты (почти как React) | `document.createElement` вручную |
| Состояние | `useState`/`useEffect` (знакомо) | свои переменные + вызовы render |
| Переиспользование | компоненты | функции-фабрики элементов |
| Миграция с React | **почти без изменений** (`react` → `preact`) | полная переписка |
| Обработка событий | декларативно `onClick` | `addEventListener` вручную |
| Ручной DOM | не нужен | везде |
| Строки кода | ~40 (пример) | ~35 (пример), но растёт на сложном UI |
| Порог входа | низкий (знаком React API) | средний |

**Радикальный факт:** миграция React → Preact делается через алиас
`react` → `preact/compat`, часто **без правки кода**. Можно заменить
даже без переписывания компонентов.

## Итоговое сравнение

| Критерий | React (текущий) | Preact | Vanilla TS |
| -------- | --------------- | ------ | ---------- |
| Размер (gzip) | 61.5 КБ | **5.7 КБ** | **0.6 КБ** |
| Скорость (много обновлений) | средняя | **высокая** | низкая (без ручной оптимизации) |
| Простота миграции | — | **очень простая** | сложная (переписать) |
| Удобство UI | высокое | **высокое** | среднее |
| Зависимостей | много (react, radix) | 1 (preact) | **0** |
| Риск ошибок при переписывании | — | **низкий** | высокий |

## Рекомендация

### ✅ Preact — оптимальный выбор

Причины:

1. **Размер падает в ~10 раз** (61.5 → 5.7 КБ gzip) — **при отказе от Radix UI**.
2. **Скорость выше** текущего React (тот же diff-подход, меньше ядро).
3. **Радикально меньше зависимостей** — одна библиотека вместо десятка Radix.
4. **Минимум переписывания**: в popup используются лишь `accordion` и `button`
   из Radix — их заменяют небольшими собственными компонентами Preact.
5. Сохраняется привычная модель компонентов/хуков.

### ⚠️ Чего делать НЕ нужно

Не стоит рассчитывать на алиас `react` → `preact/compat` при сохранении Radix:
по замерам бандл станет **больше** (17.5 против 12.9 КБ gzip). Preact выигрывает
только в паре с отказом от Radix.

### ⚠️ Vanilla TS — только при особых целях

Оправдан, если:
- нужен **абсолютный минимум** (popup 0.6 КБ);
- вы готовы **переписать** весь UI popup руками;
- UI простой и статичный;
- важна **нулевая зависимость** от фреймворков.

Даёт минимальный вес, но требует ручной работы с DOM и **больше кода**
на сложном UI (состояние, списки, аккордеоны, диалоги).

> Забегая вперёд: большая часть «веса» текущего popup — это **Radix UI**
> (10 пакетов), а не сам React. Поэтому замена только React на Preact
> без отказа от Radix даст меньший выигрыш, чем цифры выше. Полный переход
> на Preact «как есть» (без Radix) — и есть цель этого сравнения.

## Как воспроизвести замеры

Прототипы и бенчмарки собирались отдельно от проекта:

- **Размер:** `esbuild --bundle --minify` для идентичного UI на Preact и Vanilla.
- **Скорость:** headless Chrome + puppeteer-core, цикл полных обновлений списка.
- **Текущий React-бандл:** `npm run build` в `extension/` → `output/chrome-mv3/chunks/popup-*.js`.

Числа могут немного отличаться на другой машине, но соотношения устойчивы.

## Результат миграции (выполнено)

Popup расширения переведён с React + Radix UI на Preact. Radix заменён
на собственные компоненты (`accordion`, `button`), иконки — на `lucide-preact`.

### Фактические цифры

| Метрика | Было (React + Radix) | Стало (Preact) | Изменение |
| ------- | -------------------- | -------------- | --------- |
| popup-бандл | 199 792 Б | **55 144 Б** | −72 % |
| popup gzip | 61.5 КБ | **18.3 КБ** | −70 % |
| React/Radix в бандле | да | **нет** | — |
| Зависимости (deps) | 14 | **5** | −64 % |

### Что изменилось в коде

- `src/components/preact/accordion.tsx` — собственный аккордеон (замена Radix).
- `src/components/preact/button.tsx` — собственная кнопка.
- `src/hooks/useStorageState.ts` — переписан на `preact/hooks`.
- `src/entrypoints/popup/*` — все компоненты переведены на Preact.
- `lucide-react` → `lucide-preact`, `class` вместо `className` у иконок.
- `wxt.config.ts` / `tsconfig.json` — JSX настроен на `preact` (`jsxImportSource`).
- Удалён каталог `src/components/ui/*` (14 React/Radix-компонентов).

### Сохранилось без изменений

- Контракт `chrome.storage.local` (ключи и формат данных).
- WXT auto-import `useStorageState`.
- Внешний вид и поведение popup (проверено в headless Chrome: рендер,
  статус печати, раскрытие аккордеонов — без JS-ошибок).
