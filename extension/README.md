# 🌐 PrintNum Extension

Браузерное расширение для автоматизации работы сотрудников ПВЗ Ozon.

Расширение интегрируется с сайтом `turbo-pvz.ozon.ru` и взаимодействует приложением PrintNum для печати номеров ячеек, а также автоматизирует ряд рутинных операций через QR-коды, автоскрипты и дополнительные инструменты интерфейса.

# Возможности

[(Вернуться к началу)](#-printnum-extension)

## 📦 Автоматизация работы

- Автоматическая отправка номеров ячеек на печать.
- Автоматизация операций через QR-коды.
- Автоматизация упаковки возвратов.

## 🎨 Настройка интерфейса

- Скрытие бокового меню.
- Скрытие уведомлений.
- Скрытие возвратов.
- Скрытие рекламных баннеров.

## 🖨️ Интеграция с PrintNum

- Отправка номеров на печать.
- Проверка состояния сервиса для печати.
- **Превью QR-этикетки** (в popup):
  - ручной ввод текста (например, `ii18725308927`);
  - предпросмотр в том же макете, что печатает C-служба:
    QR слева и справа, значение по центру, последние 4 цифры — жирным;
  - размер этикетки берётся из `GET /config` (`paper`), по умолчанию 43×25 мм;
  - пока поле пустое, показывается пример (кнопки печати отключены);
  - печать через приложение PrintNum на реальный принтер
    (`POST /print-barcode`);
  - печать из браузера (тот же SVG + `window.print()`).

- **Панель настроек печати** (в popup):
  - включение/выключение печати;
  - выбор принтера и размера этикетки;
  - флаги оформления (ID, подчёркивание, гибридный формат);
  - изменения применяются сразу, перезапуск приложения не нужен.
- **Подхват штрихкода из кнопки «копировать»**: на странице Ozon нажмите
  копирование рядом со штрихкодом — значение автоматически подставится
  в генератор при следующем открытии окна расширения.

> Настройки QR-команд, автоскриптов и видимости убраны из окна расширения,
> но сами функции продолжают работать на страницах Ozon. Как вернуть их в
> интерфейс — см. [Полезные советы](#как-вернуть-убранные-функции-popup).

Выполняет следующие действия:

1. Проверить
2. На проверке
3. К выдаче
4. Изменил решение о покупке/Товар не подошёл

## Автоскрипты

### Упаковки Ozon нет в наличии

Раздел, где скрипт автоматически активируется:

```text
Отправка → Отправка перевозок → Прямой/Возвратный поток
```

Как использовать:

1. Выберите возврат для упаковки.
2. Отсканируйте товар.
3. Автоматически будет выбрано:
   - «Упаковки Ozon нет в наличии».
4. Отсканируйте новый штрихкод.
5. При появлении кнопки «Завершить» они нажмётся автоматически.
6. Повторно отсканируйте товар с новым штрихкодом.
7. Товар будет добавлен в перевозку.

Раздел, где скрипт автоматически активируется:

```text
Отправка → Отправка перевозок → Прямой/Возвратный поток
```

> ℹ️ Все тарники автоматически переносятся в любую открытую перевозку

# API взаимодействия

[(Вернуться к началу)](#-printnum-extension)

Базовый URL:

```text
http://127.0.0.1:5000
```

| Метод | Endpoint        | Назначение                     |
| ----- | --------------- | ------------------------------ |
| GET   | /               | Проверка доступности           |
| GET   | /status-printer | Доступен ли принтер            |
| GET   | /listPrinters   | Список принтеров системы       |
| GET   | /papers         | Размеры этикеток из конфига    |
| GET   | /config         | Текущие настройки печати + `features` |
| POST  | /config         | Изменение настроек             |
| POST  | /print-number   | Печать номера (`163-1`) или полки (`-88`) |
| POST  | /print-barcode  | Печать комбинированной QR-этикетки |

Пример печати номера:

```javascript
await fetch("http://127.0.0.1:5000/print-number", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    text: "123-456",
  }),
});
```

## Управление настройками из расширения

Окно расширения читает и меняет те же настройки, что и приложение
(принтер, размер этикетки, флаги оформления). Приложение подхватывает
изменения на лету — перезапускать его не нужно.

`GET /config` возвращает текущее состояние:

```json
{
  "printer": "Zebra ZD230",
  "paper": "30*20",
  "idNum": false,
  "endLine": false,
  "hybrid": false,
  "expand": 500,
  "running": true
}
```

`POST /config` принимает **частичный** объект — меняются только переданные
поля, остальные остаются как были:

```javascript
// Поменять только принтер и включить гибридный режим
await fetch("http://127.0.0.1:5000/config", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ printer: "Zebra ZD230", hybrid: true }),
});
```

Ответ — полный актуальный конфиг. Ошибки:

| Статус | Когда |
| ------ | ----- |
| `400`  | тело не JSON или не объект (массив/строка) |
| `500`  | не удалось записать `config.json` |

Особенности:

- неизвестные ключи **игнорируются** — новое расширение не сломает старое приложение;
- значения неверного типа игнорируются (`"hybrid": "yes"` ничего не поменяет);
- `expand` не может быть меньше `1` — значение поднимается до `1`;
- `papers` — пустой массив игнорируется (иначе не осталось бы вариантов выбора),
  нестроковые элементы отбрасываются, пробелы обрезаются;
- в логе приложения появляется строка `[config] изменён из расширения: ...`.

## Размеры этикеток

Список размеров хранится в `config.json` (поле `papers`), а не в коде —
поэтому его можно менять без пересборки:

```json
{
  "paper": "30*20",
  "papers": ["30*20", "40*30", "55*33"]
}
```

Расширение берёт список через `GET /papers`, поэтому добавленный размер
сразу появляется в его окне:

```javascript
const res = await fetch("http://127.0.0.1:5000/papers");
const { papers } = await res.json();  // ["30*20", "40*30", "55*33"]
```

Если поля `papers` в конфиге нет или оно пустое — используются восемь
значений по умолчанию (`30*20`, `40*30`, `43*25`, `50*70`, `58*40`,
`60*40`, `75*120`, `100*150`).

> ⚠️ Эндпоинты не требуют аутентификации. Сервер слушает только
> `127.0.0.1`, но менять настройки может любой локальный процесс.
> Для локального инструмента это приемлемо, но стоит учитывать.

# Полезные советы

[(Вернуться к началу)](#-printnum-extension)

## Как WXT находит скрипты

В `wxt.config.ts` **не перечисляются** ни content-scripts, ни background — WXT
подхватывает их автоматически из `src/entrypoints/` по соглашению об именах.

| Файл в `src/entrypoints/` | Что получается в сборке | Подключается к страницам |
| --- | --- | --- |
| `*.content.ts` | `content-scripts/*.js` | да, через `manifest.json` |
| `background.ts` | `background.js` | да, service worker |
| `popup/` | `popup.html` + `chunks/` | нет, окно расширения |

Поэтому **отдельный файл-скрипт попадает в сборку просто потому, что
лежит в `entrypoints/`**, а не потому, что его кто-то импортирует. Не
путайте это с popup: там работает обычный tree-shaking по импортам.

## Что попадает в сборку, а что нет

- **Content-scripts и background** — попадают всегда, если файл есть в
  `entrypoints/`. Регистрируются в `manifest.json` и работают на
  `turbo-pvz.ozon.ru`. Проверить:

  ```bash
  python3 -c "import json; print(json.load(open('output/chrome-mv3/manifest.json'))['content_scripts'])"
  ```

- **Popup** — попадает только то, что достижимо по импортам от
  `popup/index.html`. Всё остальное отсекается автоматически.

Это означает: **если убрать импорт из `popup/App.tsx`, модуль перестанет
попадать в сборку, но останется в проекте.** Специально ничего исключать
не нужно.

## Как вернуть убранные функции popup

Настройки QR-команд, автоскриптов и видимости **остаются в проекте**, но
больше не показываются в окне расширения. Чтобы вернуть, добавьте импорты
в `src/entrypoints/popup/App.tsx`:

```tsx
import QrCommands from "./qrCommands";
import Autoscript from "./autoscript";
import Hide from "./hide";
import Help from "./Help";
```

и отрисуйте их внутри разметки — как раньше, в аккордеоне
«Дополнительные возможности».

> ⚠️ Важно: содержимое этих настроек доступно только из popup. Сами
> функции на страницах Ozon (скрытие баннеров, QR-команды, автоскрипты)
> продолжают работать независимо — их обслуживают отдельные
> `*.content.ts`.

## Мёртвый код: удалять или нет

Если модуль больше никто не импортирует (например, после удаления раздела
из popup), он всё равно **не попадает в сборку** — Vite отсекает его
автоматически. На размер `output/` такие файлы не влияют.

| Ситуация | Что делать |
| --- | --- |
| Функция может вернуться | **Ничего** — файл в проекте, в сборку не идёт |
| Хочется чистый репозиторий | Удалить; код останется в истории git |
| Нужно убрать из проверки типов | Добавить путь в `exclude` в `tsconfig.json` |
| Нужно сохранить, но убрать из живого кода | Вынести в `src/_unused/` |

Проверить, что модуль действительно мёртвый:

```bash
# ищем импорты конкретного модуля, исключая его самого
grep -rn 'from "\./Help"' src/ | grep -v "popup/Help"
```

## Подхват штрихкода из кнопки «копировать»

На страницах Ozon есть кнопки копирования (штрихкод, номер отправления,
название товара). При клике по кнопке рядом со штрихкодом значение
подставляется в генератор в окне расширения.

**Как это работает.** Значение **не читается из буфера обмена** — оно уже
есть в DOM, в скрытом `textarea` рядом с кнопкой:

```html
<div class="_copy_1ulht_50 _copyButton_o3a5g_142">
  <button>…<svg class="_icon_1ulht_18"></svg></button>
  <textarea class="_textarea_1ulht_54" value="ii8923223139"></textarea>
</div>
```

Content-script `labelCopy.content.ts` слушает клики и читает `textarea.value`.
Отсюда два следствия:

- **не нужны права на буфер обмена** (`clipboardRead`) — DOM и так доступен;
- **не ломается при смене текста уведомлений** — формулировки Ozon не парсятся.

**Фильтрация.** Ozon копирует три разных типа значений, поэтому в хранилище
попадают только штрихкоды — по формату `ii` + 9–14 цифр
(`LABEL_BARCODE_RE` в `utils/constants.ts`):

| Что копируется | Пример | Попадает в генератор |
| --- | --- | --- |
| Штрихкод отправления | `ii8923223139` | ✅ да |
| Номер отправления | `0114344617-0034-1` | нет |
| Название товара | `Куртка KRONOS` | нет |

**Передача значения.** В момент клика окно расширения обычно закрыто,
поэтому передача идёт через `chrome.storage.local` (ключ `lastCopiedLabel`),
а не напрямую:

```text
страница Ozon → labelCopy.content.ts → chrome.storage.local
                                              ↓
                          BarcodeGenerator читает при открытии
```

Генератор также подписан на `chrome.storage.onChanged` — если окно открыто,
значение подставляется сразу.

**Селекторы и хэши.** Имена классов в разметке Ozon содержат хэш сборки
(`_copyButton_o3a5g_142`), который меняется при их обновлениях. Поэтому
в `SELECTORS` используются частичные совпадения (`[class*="_copyButton_"]`).
Если Ozon переименует префикс — править нужно только `utils/constants.ts`.

**Правило подстановки.** Если в поле генератора уже что-то введено вручную,
при открытии окна оно не затирается — новое значение перезаписывает только
пустое поле (либо приходит через `onChanged`, когда окно открыто).

## Автопечать по ответам Ozon (ячейки и полки)

Расширение умеет печатать не только по изменению DOM, но и по ответам
XHR. Это добавляет **полки**, которых в DOM-режиме нет.

### Цепочка

```text
Ozon XHR response
  → pageHook.js (MAIN world, перехват XHR/fetch)
  → window.postMessage
  → sendPrintNum.content.ts (ISOLATED, bridge)
  → background.ts (service worker)
  → POST /print-number
  → PrintNum (C-служба) → принтер
```

### Какие ответы перехватываются

| Эндпоинт | Поле | Что печатается |
| --- | --- | --- |
| `/api2/address-storage/Movement/put/v2` | `articlePositions[0].address` | ячейка `163-1` |
| `.../MicroFFTransferApi/TransferByBarcodeArticle` | `transferSuccess.cell` | полка `-88` |
| `.../MicroFFTransferApi/TransferPackingArticle` | `success.cell` | полка `-57` (переупаковка) |

Полка кодируется **ведущим дефисом**, а не буквой `П`: `"Ozon Полка-88"` →
`-88`. Такой текст проходит валидацию `/print-number` (цифры/дефис/пробел)
и печатается одной крупной строкой. Отдельного эндпоинта нет.

### Режимы

Настройки лежат в `chrome.storage.local` под ключом `autoPrint` и меняются
в popup (панель «Автопечать при размещении»):

| Режим | Поведение |
| --- | --- |
| `off` | автопечать выключена |
| `dom` | как раньше: по изменению списка на странице приёмки |
| `xhr` | только перехват ответов; рекомендуется |
| `both` | DOM + перехват, для отладки (дубли гасит `overlapGuardMs`) |

При обновлении расширения существующие пользователи остаются на `dom`,
новые установки получают `xhr` (`chrome.runtime.onInstalled`).

### Дедупликация

- `Movement/put/v2` — одна и та же ячейка подряд не печатается в пределах
  `dedupeMs` (по умолчанию 5000 мс).
- Полки — печатаются всегда; в режиме `both` повтор той же полки в пределах
  `overlapGuardMs` (1000 мс) гасится, чтобы DOM не дублировал XHR.

### Совместимость со старым PrintNum

Перед первой печатью полки background читает `GET /config` и проверяет
`features`:

```json
{"features":["shelf-dash"]}
```

Если поля нет (старая C-служба), полки не печатаются, а в popup появляется
предупреждение «Обновите PrintNum». Ячейки продолжают работать.

### Chrome 109 / Windows 7

Manifest-ключ `content_scripts[].world: "MAIN"` поддерживается только с
Chrome 111. Поэтому `pageHook` собирается как unlisted script и внедряется
из background через:

```ts
chrome.scripting.executeScript({ world: "MAIN", files: ["pageHook.js"] });
```

Это работает с Chrome 95+ (и Firefox 102+), то есть и на последнем Chrome
для Windows 7.

> После обновления расширения перезагрузите открытые вкладки Ozon (F5):
> старый `pageHook` в MAIN-мире уже не заменится без перезагрузки страницы.

### Отладка

- В dev-сборке доступен `window.PrintNumHook` (`emit`, `parsePlacement`).
- Настройки: `chrome.storage.local` → `autoPrint`.
- Последнее событие: `lastAutoPrintEvent` (текст, статус, ошибка, время) —
  показывается в popup.
- Логи: `[PrintNum:auto]` в консоли service worker, `[PrintNum:hook]` на
  странице.

## Не путайте `hide/` и `hide*.content.ts`

Это разные вещи, хотя названия похожи:

- `src/entrypoints/hideMenu.content.ts` и прочие `hide*.content.ts` —
  **рабочие** скрипты для страниц Ozon;
- `src/entrypoints/popup/hide/` — **интерфейс настроек** для них в popup
  (сейчас не подключён).

Удаление `popup/hide/` не сломает скрытие баннеров на Ozon.

## Эмулятор сканера ШК (только для разработки)

Физический сканер штрихкодов работает как HID-клавиатура: очень быстро «набирает»
символы штрихкода и завершает ввод клавишей Enter. Чтобы проверять обработку
сканирования **без реального сканера**, в dev-сборке доступен эмулятор.

### Как запустить

1. Установите зависимости (только в первый раз):

   ```bash
   npm install
   ```

   > Без `node_modules` команда `npm run dev` выдаст `wxt: command not found`.

2. Соберите расширение в режиме разработки:

   ```bash
   npm run dev
   ```

   WXT соберёт расширение в `extension/output/chrome-mv3` и откроет Chrome.

3. Если браузер не открылся сам — загрузите распакованное расширение
   из `output/chrome-mv3` в браузер
   (`chrome://extensions` → «Загрузить распакованное»).
4. Откройте страницу Ozon и DevTools (F12).
5. **Переключите контекст Console на `PrintNum`** — в выпадающем списке рядом
   с `top` (content script живёт в изолированном мире, иначе вы получите
   `PrintNumScanner is not defined`).
6. В консоли вызовите:

   ```js
   // одиночное сканирование
   PrintNumScanner.simulate("123-47");

   // серия сканирований с паузами между ними
   PrintNumScanner.simulateSequence(["123-47", "500-47", "КГТ-1"], 1500);
   ```

Эмулятор генерирует реальные события `keydown` на `window` — точно так же,
как это делает сканер. Поэтому проверяется вся боевая цепочка:
`utils/listener.ts` → content script → отправка номера.

В консоли появится:

```
[PrintNum:scanner] отсканировано: "123-47"
[PrintNum:scanner] обработка номера: "123-47"
[PrintNum:scanner] номер "123-47" отправлен в PrintNum
```

### Параметры

| Функция                                                | Описание                                          |
| ------------------------------------------------------ | ------------------------------------------------- |
| `simulate(value, charDelay = 15)`                       | Симулирует сканирование одного ШК                 |
| `simulateSequence(values, delayMs = 1500, charDelay = 15)` | Серия сканирований с паузой между ними |
| `onSimulatedScan(callback)`                             | Подписка на результат симулированного сканирования |

### Важно

- Эмулятор **доступен только в dev-режиме** (`npm run dev`). В production-сборке
  (`npm run build`) код эмулятора полностью вырезается из бандла — в рабочем
  расширении его нет.
- Для полного сквозного теста (сканирование → печать) запустите PrintNum в режиме
  эмуляции печати (`printnum.exe --dry-run`). Тогда номер не уйдёт на принтер,
  а разбор этикетки будет выведен в терминал приложения (на Windows — ещё и
  сохранён как превью).
- Порт приложения по умолчанию — `5000`. Если он изменён (`PRINTNUM_PORT` в
  приложении), укажите тот же порт в `extension/.env` (`VITE_PRINTNUM_PORT`)
  и пересоберите расширение.
