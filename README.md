# <img src="./public/favicon.ico" width="50em"> PrintNum — Печать ячеек (Ozon)

Бесплатное Windows-приложение для автоматической печати номеров ячеек и складских этикеток Ozon. Программа интегрируется с сайтом Ozon через браузерное расширение и помогает ускорить процессы приемки товаров, выдачи заказов, возвратов, упаковки и работы на складе.

## 🚀 Быстрый старт

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

> 📖 **Первый запуск?** Пошаговая инструкция со всеми деталями и решением проблем — в [`docs/first-run.md`](./docs/first-run.md).

1. **Скачайте приложение**: Перейдите в раздел **Releases** и скачайте последнюю версию программы (`printnum.exe`).
2. **Запустите PrintNum**: Положите `printnum.exe` в удобную папку и запустите двойным кликом. Установка не требуется.
3. **Установите принтер в Windows**: добавьте принтер и вручную задайте в его драйвере тот же размер этикетки, что будете указывать в PrintNum (иначе этикетка напечатается пустой или смещённой).
4. **Настройте параметры**:
   - **Принтер** — выберите доступный принтер Windows.
   - **Размер этикетки** — задайте ширину и высоту.
   - **Стиль этикетки** — настройте формат текста и расположение.

5. **Установите расширение для браузера:**
   - Откройте страницу расширения в Chrome Web Store по [ссылке](https://chromewebstore.google.com/detail/printnum-%D0%BF%D0%B5%D1%87%D0%B0%D1%82%D1%8C-%D1%8F%D1%87%D0%B5%D0%B5%D0%BA-ozo/pebpcdibpeodhdkbeniijidffpfpiagn) **или** вручную найдите расширение **«PrintNum - Печать Ячеек (Ozon)»** в Chrome Web Store.
   - Нажмите **«Установить»** и подтвердите установку расширения.

6. **Перезагрузите страницы Ozon**.

7. **При первой отправке номера ячейки** (иногда при первой или второй попытке после сканирования) может появиться окно браузера с запросом на разрешение обмена данными с **localhost**. Нажмите **«Разрешить»** (или **Allow**). В дальнейшем этот запрос больше не появится.

8. **Готово!** Теперь расширение **«PrintNum - Печать Ячеек (Ozon)»** автоматически передает номера ячеек в программу PrintNum, запущенную на вашем компьютере.

## Стек технологий

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

| Компонент     | Технология                                                                       | Описание                              |
| ------------- | -------------------------------------------------------------------------------- | ------------------------------------- |
| **Desktop**   | [Rust](https://www.rust-lang.org/) 1.70+ + [Slint](https://slint.dev/) 1.x       | Нативный GUI (Windows 7+)             |
| **Backend**   | Rust + [`tiny_http`](https://github.com/tiny-http/tiny-http) 0.12               | Встроенный HTTP API для печати        |
| **Печать**    | Rust + [`windows`](https://github.com/microsoft/windows-rs) (Win32 GDI / Spooler) | Печать этикеток, статус, очередь      |
| **Extension** | [WXT](https://wxt.dev/) + Preact + TypeScript                               | Браузерное расширение Ozon            |

> **Весь backend и frontend написан исключительно на Rust.** Python, Node.js и WebView2 для работы приложения не требуются.

## Архитектура

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

Проект использует модульную архитектуру для разделения ответственности между компонентами:

### 🎨 **GUI (Rust + Slint)**

- Управляет пользовательским интерфейсом и настройками приложения.
- Показывает статус HTTP-сервера и принтера.
- Сохраняет настройки в пользовательском каталоге приложения (см. таблицу ниже).
- Работает нативно через GDI/Direct2D — **без WebView2**, что обеспечивает совместимость с Windows 7.

### 🔧 **Backend (Rust + tiny_http)**

- Запускает HTTP REST API сервер на `http://127.0.0.1:5000` в отдельном потоке внутри того же процесса.
- Читает конфигурацию.
- Проверяет состояние принтера и отправляет текст на печать.
- Совместим по контракту с прежним Flask backend — браузерное расширение не менялось.

### 🖨️ **Печать (Rust + Win32 GDI/Spooler)**

- Полный аналог прежней логики на pywin32 (1:1): подбор размеров, шрифты, жирность, подчёркивание, КГТ-логика.
- `EnumPrinters` — список принтеров.
- `OpenPrinter` + `GetPrinter` — статус принтера.
- `OpenPrinter(ADMINISTER)` + `SetPrinter(PURGE)` — очистка очереди.
- GDI (`CreateDC`, `CreateFont`, `TextOut`) — печать этикетки.

### 🌐 **Браузерное расширение (WXT + Preact + TypeScript)**

- Работает на страницах Ozon и отправляет номера ячеек в программу PrintNum на ПК.
- Автоматизирует процессы выдачи, приемку, возврат товаров и упаковку.
- Скрывает элементы интерфейса и управляет поведением страницы.

## Требования

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

**Для работы приложения (пользователю):**

- **ОС**: Windows 7 SP1 x64 и выше (Windows 10/11 также поддерживаются).
  - На Windows 7 требуется установить обновление [KB2533623](https://support.microsoft.com/help/2533623) (обычно уже установлено).
- **Браузер**: Chromium-совместимый браузер (Chrome, Yandex, Edge).
- **Дополнительно**: ничего. Python, Node.js и WebView2 **не нужны** — всё собрано в один `printnum.exe`.

**Для сборки из исходников:**

- **Rust**: nightly-тулчейн с компонентом `rust-src` (задаётся автоматически через `src-printnum/rust-toolchain.toml`). Nightly нужен для `-Z build-std`.
- **MSVC Build Tools** (C++ toolchain) для target `x86_64-win7-windows-msvc`.
- **Node.js**: 18+ LTS — **только** для сборки браузерного расширения (`extension/`).

### Поддерживаемые платформы

| Платформа | Статус | Что работает |
| --------- | ------ | ------------ |
| **Windows 7 SP1 x64 / 10 / 11** | ✅ Поддерживается | Всё: GUI, HTTP API, печать, список/статус принтеров |
| **macOS / Linux** | 🛠 Только для разработки | GUI, HTTP API, тесты логики. **Печать недоступна** (нет Win32 GDI/Spooler) |

> ⚠️ **macOS и Linux не являются поддерживаемыми пользовательскими платформами.**
> Проект собирается и запускается на них, чтобы можно было вести разработку и
> тестировать GUI/API без Windows. Печать и все функции принтера там заменены
> заглушками: список принтеров пуст, статус всегда «недоступен».
> Для приложения на macOS/Linux потребовалась бы отдельная реализация печати
> (CUPS + Core Graphics) — она не заявлена и не реализована.

## ❓ Часто задаваемые вопросы

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

### Какие браузеры поддерживаются?

PrintNum работает с Chromium-браузерами: **Google Chrome**, **Яндекс Браузер** и **Microsoft Edge**.

### Нужно ли устанавливать расширение?

**Да.** Для работы PrintNum необходимо установить браузерное расширение **«PrintNum — Печать Ячеек (Ozon)»**.

Откройте **Интернет-магазин Chrome**, найдите расширение **«PrintNum — Печать Ячеек (Ozon)»** и нажмите **«Установить»**. После установки перезагрузите страницы Ozon, если они были открыты.

### Как понять, что программа готова к работе?

Запустите PrintNum, выберите принтер и убедитесь, что он отображается в настройках приложения. После этого откройте страницу Ozon и попробуйте отправить номер ячейки на печать.

### Почему номер ячейки не печатается?

Проверьте следующие моменты:

- приложение PrintNum запущено;
- браузерное расширение установлено и включено;
- открытая страница Ozon была обновлена после установки расширения;
- выбран корректный принтер;
- принтер подключен и находится в состоянии «Готов».

### Почему этикетка печатается пустой или текст расположен не по центру?

Если в настройках PrintNum размер этикетки указан правильно, но принтер печатает пустую этикетку, обрезает текст или смещает его относительно центра, то, скорее всего, в настройках самого принтера установлен другой размер бумаги.

Откройте **Настройки принтера** в Windows и вручную установите тот же размер этикетки, который указан в PrintNum. Ширина и высота этикетки в приложении и в драйвере принтера должны полностью совпадать.

После изменения настроек рекомендуется выполнить пробную печать. В большинстве случаев это устраняет проблемы с пустой печатью, смещением текста и неправильным позиционированием этикетки.

### Какие принтеры поддерживаются?

PrintNum поддерживает любые принтеры, доступные в Windows. Наиболее удобно использовать термопринтеры для печати небольших этикеток, однако приложение совместимо и с другими моделями принтеров.

### Можно ли изменить размер и оформление этикетки?

Да. В настройках приложения можно изменить размеры этикетки, формат отображения текста и другие параметры печати.

### Где сохраняются настройки?

Все выбранные параметры (принтер, размеры этикетки, стиль печати и другие настройки) автоматически сохраняются в `config.json` и восстанавливаются при следующем запуске приложения.

Расположение данных зависит от платформы:

| Платформа | Каталог данных |
| --------- | -------------- |
| **Windows** | `%APPDATA%\PrintNum\` (например, `C:\Users\<Имя>\AppData\Roaming\PrintNum\`) |
| **macOS** (только разработка) | `~/Library/Application Support/PrintNum/` |
| **Linux** (только разработка) | `$XDG_CONFIG_HOME/PrintNum/` или `~/.config/PrintNum/` |

### Требуется ли постоянное подключение к Интернету?

Интернет необходим только для работы с сайтом Ozon. Обмен данными между браузерным расширением и приложением PrintNum происходит локально на вашем компьютере.

### Приложение бесплатное?

Да. PrintNum распространяется бесплатно и предназначено для автоматизации печати номеров складских ячеек и этикеток Ozon.

## API документация

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

Backend предоставляет REST API на Rust (`tiny_http`) на порту `5000`.
Контракт полностью совместим с браузерным расширением.

| Метод    | Эндпоинт          | Описание                     | Ответ                            |
| -------- | ----------------- | ---------------------------- | -------------------------------- |
| **GET**  | `/`               | Проверка доступности сервера | `{"status": true}`               |
| **GET**  | `/status-printer` | Проверка состояния принтера  | `{"printerOnline": true/false}`  |
| **GET**  | `/listPrinters`   | Получение списка принтеров   | `{"listPrinters": ["Принтер1"]}` |
| **POST** | `/print-number`   | Печать номера ячейки         | `OK`                             |
| **POST** | `/print-barcode`  | Печать штрихкода Code128    | `OK`                             |

**Базовый URL**: `http://127.0.0.1:5000`

### Печать штрихкода

`POST /print-barcode` принимает JSON:

| Поле       | Тип   | По умолчанию | Описание                        |
| ---------- | ----- | ------------ | ------------------------------- |
| `text`     | string | —           | текст ШК (например, `ii18725308927`) |
| `moduleMm` | number | `0.25`      | ширина модуля, мм               |
| `heightMm` | number | `10`        | высота полосок, мм              |

Под полосками печатается читаемый текст (HRI). Кодирование — Code128 Auto.

```bash
curl -X POST http://127.0.0.1:5000/print-barcode \
  -H "Content-Type: application/json" \
  -d '{"text":"ii18725308927","heightMm":10,"moduleMm":0.25}'
```

### Native Messaging (без порта)

Помимо HTTP, приложение умеет работать через **Native Messaging** — прямой
обмен с расширением через stdin/stdout, без открытого порта.
Запускается флагом `printnum.exe --native-host`.

Поддерживаются те же команды (`ping`, `print-number`, `print-barcode`,
`status-printer`, `list-printers`). Полная инструкция по регистрации —
в [`docs/native-messaging.md`](./docs/native-messaging.md).

HTTP-сервер работает внутри процесса приложения, поэтому отдельный watchdog
и завершение по неактивности не требуются — сервер живёт, пока открыто приложение.

### Смена порта

Порт по умолчанию — `5000`. Его можно задать:

- **переменной окружения** `PRINTNUM_PORT` (высший приоритет);
- **файлом `.env`** рядом с `printnum.exe` (или в текущей рабочей директории).

Пример `.env` (см. `src-printnum/.env.example`):

```env
PRINTNUM_PORT=6000
```

> ⚠️ **Важно:** порт задаётся и в приложении, и в расширении. Чтобы расширение
> нашло приложение, тот же порт нужно указать в `extension/.env`
> (`VITE_PRINTNUM_PORT`) и **пересобрать расширение** (`npm run build`):
>
> ```env
> VITE_PRINTNUM_PORT=6000
> ```
>
> Порт в расширение подставляется на этапе сборки, а не во время работы,
> так что без пересборки изменение не подхватится.

## 🧪 Режим эмуляции печати (dry-run)

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

Для проверки логики и вёрстки этикетки **без принтера** предусмотрен режим эмуляции.
В нём печать на принтер не выполняется: вместо этого этикетка рендерится offscreen
(тем же GDI-кодом) и сохраняется превью + JSON-отчёт.

**Включение:**

```bat
:: через аргумент командной строки
printnum.exe --dry-run

:: или через переменную окружения
set PRINTNUM_DRY_RUN=1
printnum.exe
```

В интерфейсе появляется индикатор **«РЕЖИМ ЭМУЛЯЦИИ»** в нижней панели.

**Что сохраняется** в каталоге `previews` (рядом с `config.json`, см. таблицу путей выше) для каждого вызова `/print-number`:

- `label_<текст>_<время>.bmp` — отрендеренная этикетка (белый фон, реальные шрифт/позиции);
- `label_<текст>_<время>.json` — отчёт с вычисленными параметрами:

```json
{
  "text": "500-47",
  "main_text": "47.",
  "header_text": "500-",
  "is_bold": true,
  "is_underlined": false,
  "paper": "30*20",
  "label_px": { "width": 239, "height": 159 },
  "main_font_height_px": 71,
  "main_rect": { "x": 85, "y": 55, "w": 68, "h": 62 }
}
```

Это позволяет проверить без принтера:

- бизнес-логику (swap, жирность, дефисы, КГТ);
- подбор размера шрифта;
- позиционирование header/main;
- соответствие размеров этикетки (мм → пиксели, DPI 203).

В терминал приложения при этом выводится разбор номера:

```
[dry-run] Разбор номера:
  Вход:        "500-47"
  Основной:    "47."
  Колонтитул:  "500-"
  Жирный:      да
  Рокировка:   да
  Подчёркивание: нет
  Этикетка:    30*20 мм
  Параметры:   hybrid=true, idNum=true, endLine=false, expand=500
```

**Проверка без запуска принтера:**

```bash
curl -X POST http://127.0.0.1:5000/print-number \
  -H "Content-Type: application/json" -d "{\"text\":\"500-47\"}"
```

> 🧪 Подробная инструкция по обоим эмуляторам (печати и сканера ШК) — в
> [`docs/emulation-testing.md`](./docs/emulation-testing.md).

> На macOS/Linux эмуляция не рендерит изображение (нет GDI), но **разбор номера
> выводится в терминал** — этого достаточно, чтобы проверить логику без Windows
> и принтера. Полные BMP/JSON-превью создаются только на Windows.

### Эмуляция сканирования ШК (в расширении)

Чтобы проверить полную цепочку «сканирование → печать» без физического сканера,
в dev-сборке расширения есть эмулятор. Он генерирует те же события `keydown`,
что и реальный сканер. Подробнее — в
[README расширения](./extension/README.md#эмулятор-сканера-шк-только-для-разработки).

```js
// в консоли страницы Ozon (после npm run dev)
PrintNumScanner.simulate("123-47");
PrintNumScanner.simulateSequence(["123-47", "500-47", "КГТ-1"], 1500);
```

## Разработка

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

1. **Клонируйте репозиторий**:

   ```bash
   git clone https://github.com/kirill18734/PrintNum.git
   cd PrintNum
   ```

2. **Запустите приложение в режиме разработки** (папка `src-printnum`):

   ```bash
   cd src-printnum
   cargo run
   ```

   Приложение соберёт Slint-интерфейс, запустит HTTP-сервер на `http://127.0.0.1:5000`
   и откроет нативное окно.

   Порт можно изменить через `.env` (см. `src-printnum/.env.example`)
   или переменную окружения `PRINTNUM_PORT`.

   >  **Разработка на macOS/Linux:** `cargo run` работает, но печать и функции
   > принтера заменены заглушками (список принтеров пуст, статус «недоступен»).
   > Это режим разработки, а не поддержка платформы. Чтобы проверить API и GUI,
   > этого достаточно; для реальной печати нужна Windows.

3. **Запустите приложение в режиме эмуляции печати** (без принтера):

   ```bash
   cargo run --release -- --dry-run
   ```

   Подробнее — в [`docs/emulation-testing.md`](./docs/emulation-testing.md).

4. **Запустите тесты** (бизнес-логика печати и пути данных):

   ```bash
   cargo test
   ```

5. **Проверьте сборку под Windows** (с macOS/Linux — только проверка типов):

   ```bash
   cargo check --target x86_64-win7-windows-msvc -Z build-std=std,panic_abort
   ```

   Боевой таргет — `x86_64-win7-windows-msvc` (не обычный `x86_64-pc-windows-msvc`).
   Он требует nightly-тулчейн с компонентом `rust-src` (см. `rust-toolchain.toml`):

   ```bash
   rustup toolchain install nightly --component rust-src
   ```

6. **Разработка расширения**:
   см. [Документация расширения](https://github.com/kirill18734/PrintNum/tree/main/extension)

## Сборка и установка

[(Вернуться к началу)](#printnum--печать-ячеек-ozon)

### Сборка под Windows

На машине с Windows (MSVC toolchain):

```bat
cd src-printnum
build-windows.bat
```

или вручную:

```bat
cd src-printnum
cargo build --release --target x86_64-win7-windows-msvc -Z build-std=std,panic_abort
```

Готовый бинарник: `src-printnum\target\x86_64-win7-windows-msvc\release\printnum.exe`.

Благодаря статической линковке CRT (`+crt-static`) на целевую машину не нужно
устанавливать Visual C++ Redistributable.

#### Почему специальный таргет `x86_64-win7-windows-msvc`

Это ключ к запуску на **Windows 7 SP1**:

- обычный `x86_64-pc-windows-msvc` собирает стандартную библиотеку Rust,
  которая статически импортирует `WaitOnAddress`/`WakeByAddressSingle`
  (появились только в Windows 8) — на Win7 приложение падает с ошибкой
  «точка входа в процедуру не найдена»;
- таргет с суффиксом `win7` собирается с `vendor = "win7"`: std загружает эти
  функции динамически через `LoadLibrary` и работает без них;
- версия Slint зафиксирована на `=1.13.0` (см. `Cargo.toml`), потому что
  более новые версии тянут `SystemParametersInfoForDpi` — функции Per-Monitor
  DPI, которой также нет в Windows 7.

Проверить совместимость готового exe можно так (на Windows):

```bat
dumpbin /imports target\x86_64-win7-windows-msvc\release\printnum.exe
```

В списке импортов не должно быть `ForDpi`, `WaitOnAddress`, `WakeByAddress*`,
`api-ms-win-crt-*`, `VCRUNTIME*`, `MSVCP*` — только системные DLL
(`kernel32`, `user32`, `gdi32`, `winspool.drv` и т.п.).

Кросс-сборка под Win7 с macOS/Linux (MSVC-линкер не нужен):

```bash
cargo install cargo-xwin
cd src-printnum
cargo xwin build --release \
    --target x86_64-win7-windows-msvc \
    -Z build-std=std,panic_abort
```

### Сборка под macOS (только для разработки)

> ⚠️ macOS-сборка **не умеет печатать** (нет Win32 GDI/Spooler). Это режим
> разработки: GUI + HTTP API + эмуляция. Для рабочей печати нужна Windows.

На машине с macOS (нужны Rust и Xcode Command Line Tools):

```bash
cd src-printnum
./build-macos.sh
```

или вручную:

```bash
cd src-printnum
cargo build --release                        # target/release/printnum
cargo install cargo-bundle                    # один раз
cargo bundle --release                        # .app + .dmg
```

Результат:

- `target/release/printnum` — исполняемый файл (запуск из терминала);
- `target/release/bundle/osx/PrintNum.app` — .app-бандл (запуск двойным кликом);
- `target/release/bundle/dmg/PrintNum.dmg` — .dmg-образ для распространения.

### Упаковка браузерного расширения

```bash
cd extension
npm install          # если ещё не сделано
npm run build        # → output/chrome-mv3
npm run zip          # → output/printnum-<версия>-chrome.zip
```

Готовый `output/printnum-<версия>-chrome.zip` загружается в
[Chrome Web Store](https://chrome.google.com/webstore/devconsole) или
распаковывается для локальной установки.

Для Firefox:

```bash
npm run build:firefox
npm run zip:firefox
```

### Установка (Windows)

Скопируйте `printnum.exe` на целевую машину и запустите. Приложение не требует
установки и работает с Windows 7 SP1 x64 и выше.
